## 2. Best Practices

- Frontend fixed-output derivation uses `npmDepsHash`, verified against the real
  `frontend/package-lock.json` (not left as a placeholder — see Build Validation
  below for the real hash and how it was obtained).
- Backend derivation filters `src` to exclude `frontend/`, `target/`, `node_modules`,
  `.github/`, `nix/` from the Nix store input, keeping the build's declared input
  minimal and avoiding accidental cache invalidation from unrelated files (e.g. this
  very review doc) between rebuilds.
- Default `package` wiring uses an overlay (`overlays.default`) applied by
  `nixosModules.default` itself, so `services.home-registry.package` defaults to
  `pkgs.home-registry` without requiring callers to thread `system`/`self` through
  by hand — avoids a common footgun in flake-based NixOS modules where `package` has
  no usable default outside `eachSystem`.
- `ALTER ROLE ... WITH PASSWORD :'pass'` in the DB password sync script uses `psql`'s
  `-v`/`:'var'` parameter substitution rather than shell/string-interpolating the
  password directly into SQL text — avoids SQL-injecting a password that happens to
  contain a quote, consistent with the "no naive string splitting" spirit of the
  original DATABASE_URL bug report.
- Hardening (`ProtectSystem = "strict"`, `ProtectHome`, `PrivateTmp`,
  `NoNewPrivileges`, `ReadWritePaths` scoped to `dataDir`) mirrors the project's
  existing security posture (`unsafe_code = "forbid"`, hardened multi-stage
  Dockerfile with a non-root user) without being asked for verbatim — flagged here
  per the Simplicity principle rather than silently added: this is a one-line-per-
  setting, low-risk addition since all documented app I/O is confined to `dataDir`
  and the Postgres connection.

  service-activation time from an out-of-store path.

  access to `dataDir` only.
- No `unsafe` Rust introduced (none was needed — packaging only).
